# 审查方法与常见漏项

本方法来自真实漏项，按任务影响选择检查；不要为凑“多轮”重复相同计数。

## 原图到内容

逐页对照原图和结构记录，检查上/中/下、右栏、长表底部、浮层与视口外内容。角色间内容共享不能自动推断它们共享全部连接。

高发遗漏：查看历史、更多、设置齿轮、认证/政策规则、下载/预览、折叠按钮、分页/每页条数、标签角标、身份信息、页脚。截图可见的默认值应记录为参考；只有行为规则未知，不能将可读默认值也标“等业务确认”。

示例：两张学习卡不是一句“能力/进度”即可承接；记录每卡标题、能力数、课程数、百分比、阶段、默认 Tab 和操作。数据冲突保留原值和来源，不自行修正业务公式。

## 内容到组件和范围

查当前目标包及具体公开接口。控件、Block、Pattern、纯内容布局、业务状态机、素材分别判断；资产名称存在只证明有资产。

- “Tabs + Table”还需分别指出各级 Tab 实例、variant/items/选中绑定、表列与 rowKey 及事件意图。无法确认时保持 candidate，不展示为已完成配置。
- 混合新旧视觉拆成工作项。日期事件、进度和分组表头优先核对基础能力；定制大卡/全新图形若与已有风格差距大列待评审。不要把缺口一律写成“页面自建”。
- 检查全局范围、每个区块文字、缺口描述、原图验收和 JSON 是否冲突。review 要显式排除且不能夹在 included 的实现步骤里。

## 数据到交付

固定 ID 关联来源、动作、区域、候选和工作项。检查所有可见动作都有记录，确认连接都能定位来源；未知目标仍可保留动作，不能由完整连线数量替代操作覆盖。

可审计材料应有裁剪来源、原始尺寸、参考数据、布局关系、素材清单与版本信息。手工红框仅辅助定位，不用于推定像素级设计尺寸。

旧画布按数组下标绑定时，插入一个区块可能导致所有后续高亮和需求错绑；数量相同的检查抓不到此错。检查具体 ID/语义配对，必要时在授权修改中迁移。

## 报告发现

每项写：影响 → 原图/数据证据定位 → 当前表达或行为 → 修订方式 → 验证边界。优先报告影响还原的遗漏、错误映射及越过实施边界的指令。分清：

- 原图可辨认但未登记：可以继续补齐，不要求用户重新提供。
- 资产能力尚未核实：回到目标包查证，不称为确定缺失。
- 原图未给的业务规则/设计值：明确待确认，不假设已实现。

结论按实际覆盖范围表述。结构完整性、脚本通过、截图视觉检查与用户接受是不同证据；自动化不能证明全部内容无遗漏。

## 从这次工作流暴露的失败做回归

- **只有原图阅读底稿**：截图、标题和索引不能支持 Agent 生成。检查每页四类摘要、分组字段/状态、动作、组件方案和范围是否实际可用。
- **与首页能力不一致**：拿真实样板逐项比较详情面板、缺口显示、标签定位、导出与目录交接；同色同布局不代表能力一致。
- **摘要刚补上但内容空泛**：检查是否把所有表单都写成相同的“字段以原图为准”。清晰可读的标签、单位、选项和限制必须继续辨认；例如附件 10M/5M 冲突应同时保留，不能随便挑一个。
- **全新图形与基础缺口混淆**：普通图文内容可以用基础组件组织；日历事件、进度等能力先查接口。不能因为当前没找到图表就把所有数据一起排除，也不能因为存在 Card 就承诺定制外观可还原。
- **总览有原则，局部继续要求自绘**：核对摘要、区块、工作项、验收、报告和 JSON 的相同项；review 不能通过“按原图完全还原”这样的验收重新进入执行。
- **交互计数通过但关系错误**：检查具体标签与对应原图区域、连线起点文字和目标、切换后的详情，而不是只检查 marker 出现或节点不重叠。

纠正这些问题时，修改真实数据和渲染/打包来源，再重建离线产物；不只在生成 HTML 上补一块文本，否则重新打包会丢失。

组件证据受环境限制时，先检查锁包内公开导出、类型和可访问的权威参考；报告证据止于何处，保持 candidate。只做需求画布的临时审查不要求在组件源码仓库新建开发任务，但不因此宣称已完成源码实现核实。
