# 页面组合 0px 间距漏检修正 · 2026-11-06

Scenarios 订单页的 Tabs 与 DataToolbar 外部间距为 0px，之前未进入路由测量与显式区域关系契约；仅检查通用间距数值无法判定这项缺失。

`partner-ui-review` 更新至 0.1.2：

- 在页面拥有的容器及明确声明的业务插槽中，自动发现纵向相邻的 Tabs→Toolbar/Table、Toolbar→Table，支持单层单内容业务容器。
- 将组件之间的外部距离作为页面组合检查；保留组件内部与页面插槽的最近归属边界，组件内部同类结构不适用页面推断。
- 自动发现对照 content-gap 生成 needs-review 候选，包含 0px；确认规范后的 `layoutContracts` 不符则为 must-fix。自动候选不能被算作显式契约覆盖。
- 要求用户标注路由、状态与宽度进入实测/回归，并将确认后的契约随项目保存，记录修复前失败和修复后通过。

浏览器回归覆盖：未配置关系时发现 0px、组件内部不误报、显式契约升级为 must-fix 且不重复报告、业务容器提供 16px 后通过、带容器的契约在间距再次清零时失败。

全套 189 项测试通过，0 跳过；Skill 格式校验通过；本地交付包 0.1.2 与源码内容、清单 SHA-256 一致。来源锁和 Vue/pages 版本未变；本次未安装全局 Skill 或发布交付包。

实际 Demo 验证见旁侧 Scenarios 仓库 `review/order-query-spacing-20261106.md`：订单/投标列表在 981 / 1185 / 1920px 下从 0px 修复为 16px，6 项 R9 失败消除；冒烟覆盖五个页签状态、三个宽度。项目持久契约位于 `prototype/ui-review.config.json`。

证据保存于工作区 `.artifacts/astra-order-spacing-20261106/`。该回归证明本次关系已修复，不代表所有页面布局角色均已覆盖。
